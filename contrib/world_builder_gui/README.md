# GWB Visual Builder

A dependency-free browser prototype for visually composing Geodynamic World
Builder models. It keeps the `.wb` JSON and `gwb-grid` `.grid` configuration in
sync while features are positioned and configured.

## Run

```bash
npm start
```

Then open <http://127.0.0.1:4173>.

## Test

```bash
npm test
```

The prototype supports:

- Cartesian and spherical-chunk grid setup with mesh resolution.
- Clicking or dragging continental plates, oceanic plates, subducting plates,
  faults, mantle layers, and plumes onto a 2D workspace.
- A shape editor with point-by-point and freehand drawing, straight or smooth
  geometry, arbitrary vertex addition/removal, direction reversal, and
  draggable control points. Double-clicking an edge inserts another vertex;
  there is no vertex limit.
- Moving features and connecting their nearest boundaries.
- Visible, draggable dip-direction handles and dip-angle labels for
  subducting plates and faults.
- An optional plan-view slab projection with a shaded down-dip ribbon, depth
  contours, deep-edge arrow, and live updates from dip angle and segment length.
- Per-feature internal layers generated by count or edited as exact depth
  intervals, with independent composition and temperature values. Slabs and
  faults use their native distance-from-surface layer coordinates.
- Named continental (25 km upper crust, 15 km lower crust, 60 km mantle
  lithosphere) and oceanic (8 km crust, 72 km mantle lithosphere) presets.
- Adjustable PNG/JPEG/WebP reference maps with opacity, scale, translation,
  rotation, and editable Cartesian or longitude/latitude bounds.
- A SubMachine/ORFEUS tomography explorer that loads a selected model and depth
  slice as a georeferenced background and transfers the selected area into a
  3D spherical-chunk grid.
- A separate Topography workspace with mountain, rift, plateau, island, and
  Perlin-style procedural generators; elevate, depress, and smooth brushes;
  two-click selection uplift/depression; hillshade and opacity controls; NOAA
  ETOPO relief loading; ASCII grid, XYZ/CSV, JSON and grayscale-raster import;
  and editable XYZ export.
- An EarthByte/GPlates paleogeography workspace with explicit reconstruction
  model, age, and anchor-frame controls; reconstructed continent, subduction,
  and plate-boundary overlays; bundled Merdith 2021 geometry from
  `contrib/gplates`; conversion of visible vectors to simplified editable GWB
  features; and an editable, non-quantitative paleo-relief proxy. Published
  PaleoDEM elevation grids can be imported through the same topography tools.
- Feature-specific geometry, composition, and thermal controls.
- Plan, isometric 3D-volume, spherical-globe, and depth-section views with
  visible slab volumes, segment thickness, dip labels, and cursor
  depth/distance readouts.
- Geological-material and temperature rendering modes with kelvin labels,
  a configurable temperature scale, contours, surface shading, light strength,
  and persistent dark/light interface themes.
- Persistent camera controls for zooming, rotating, and resetting every model
  view, plus mouse-wheel zoom on the canvas.
- The official Geodynamic World Builder logo from the project documentation.
- Correct separation of surface X/Y or longitude/latitude from vertical depth;
  spherical chunk grids convert editor depth bounds to native radial bounds.
- Drawing cross sections directly on the plan view.
- A searchable library generated from the official tutorials, cookbooks, and
  tested reference models, with action-gated practice lessons and a completion
  screen that can launch another tutorial from a clean temporary model.
- Lossless import and re-export of advanced World Builder parameters.
- An advanced per-feature JSON editor for parameters not yet represented by a
  dedicated graphical control.
- Live `.wb` JSON and `.grid` generation, import, export, and local autosave.
- Experimental local spatial controls: webcam hand tracking for camera navigation,
  feature/vertex/depth-handle editing, and interface activation; plus an optional
  true 3D WebGL preview with an immersive WebXR entry point on supported devices.

## Experimental spatial controls

Open **Workspaces → Utilities → Spatial Controls**. Camera processing runs in a
dedicated browser worker using the bundled MediaPipe hand-landmark model. Video
frames are not uploaded or saved. The preview can be mirrored independently of
the model coordinates, and tracking can be stopped at any time to release the
camera.

- Move one open hand to pan; pinch while moving to orbit.
- Pinch a visible feature, vertex, dip handle, thickness handle, or internal
  boundary to edit it directly. Releasing the pinch commits one undoable edit.
- In Geometry mode, pinch-hold a feature-library card, carry it onto the Plan
  canvas, and release to create the feature at that location.
- Pinch with two hands to zoom, rotate, and pan the current model view.
- Corners use a magnetic spatial target larger than the visible node. Its grab
  radius is adjustable under Tracking and calibration and the cursor changes to
  `CORNER` when a vertex will be selected.
- Optional shortcut poses use conservative three-frame stabilization: make a
  fist to cancel the active grab or hold a V sign to fit the model to view.
  Open-palm Undo/Redo swipes are separately opt-in because normal construction
  movement can resemble a swipe.
- Interface mode exposes a dwell cursor for large buttons and movable tool
  windows. Geometry mode leaves the rest of the interface untouched.
- Calibrate neutral position after changing camera placement. Adjustable
  smoothing, pinch sensitivity, and motion gain are stored locally.

The **Open XR model preview** button creates a separate Three.js/WebGL scene so
experimental immersive interaction cannot alter the trusted Canvas editor.
Desktop users can drag to orbit and use the wheel to zoom. On a WebXR headset,
one tracked-hand pinch moves the model and two pinches scale and rotate it.
Immersive VR and webcam access require a secure context in production (HTTPS;
localhost is accepted for development), browser permission, and compatible
hardware. Keyboard, mouse, and touch interaction remain available throughout.

The hand tracker is pinned in `package-lock.json`; its model provenance and
checksum are recorded in `assets/models/README.md`. The World Builder WebAssembly
runtime and hand tracker use separate workers and can run on the same page.

The implementation deliberately retains browser-native Canvas for the current
editable plan, 3D, and section views. The experimental immersive workspace uses
Three.js/WebGL as a separate renderer without changing the project model or
generators in `core.js`.

Every floating editor and scientific result workspace can be minimized without
losing its controls or computed state. Minimized windows appear in the restore
tray at the lower-right of the viewport, and their minimized state is preserved
with the local project session.

The tomography bridge requests public SubMachine depth-slice rasters through
the local Node server. It validates the model and numeric bounds and retains
the source result URL as metadata. Volumetric cubes and numeric cross-sections
remain a separate data/import workflow.

The paleogeography bridge requests GeoJSON from the public GPlates Web Service
through validated server-side endpoints. Remote geometries are kept in the
current browser session instead of local storage because global reconstructions
can contain thousands of features.

## Run GWB in the browser

The visual builder includes a WebAssembly build of the World Builder C++ engine.
It runs in a dedicated Web Worker, accepts the same `.wb` JSON and `.grid` text
that the editor already generates, and returns transferable typed arrays rather
than writing and reparsing a VTU file.

Build or refresh the browser binary with an active Emscripten SDK:

```bash
npm run wasm
```

The generated `wasm/gwb-web.js` and `wasm/gwb-web.wasm` files must be deployed
beside the interface. Production hosting should serve `.wasm` as
`application/wasm`. This first browser build is single-threaded, so it does not
require cross-origin isolation headers.

Interface code calls the stable JavaScript facade:

```js
import { gwbRuntime } from "./gwb-runtime.mjs";

const controller = new AbortController();
const result = await gwbRuntime.run({
  wbText: buildWbText(),
  gridText: buildGrid(state.settings),
  resolutionLimit: 128
}, {
  signal: controller.signal,
  onProgress: ({ phase, progress }) => {
    console.log(phase, `${Math.round(progress * 100)}%`);
  }
});
```

Calling `controller.abort()` cancels the calculation by terminating the worker.
Only one calculation can run through a runtime instance at once. The default
resolution limit is 256 cells in each direction; previews should normally use a
smaller limit for 3D models.

The result contract is:

```js
{
  dimension: 2 | 3,
  cells: [nx, ny, nz],
  compositionCount: number,
  points: Float64Array,              // interleaved XYZ
  connectivity: Uint32Array,         // quads in 2D, hexahedra in 3D
  depthWrtSurface: Float64Array,
  depthWrtReference: Float64Array,
  topography: Float64Array,
  temperature: Float64Array,
  velocity: Float64Array,            // interleaved XYZ
  tags: Int32Array,
  density: Float64Array,             // empty unless output_density = true
  composition: Float64Array          // composition-major [field][point]
}
```

The browser sampler currently supports the Cartesian and spherical `chunk`
grids generated by the visual builder, in both 2D and 3D. Native `sphere` and
`annulus` grid output remain available through `gwb-grid`.

Thermal previews can also use the experimental browser-only adaptive sampler in
`source/gwb-web/adaptive_sampler.cc`. It starts from a small quadtree (2D) or
octree (3D), queries the real `WorldBuilder::World` property engine, and refines
leaf cells when centre interpolation error, composition, tags, or topography
indicate unresolved structure. Prospective child centres are sampled as a
feature-tracking stencil, so thin plates, faults, plumes, and internal layers
can trigger refinement even when the parent corners and centre miss them.
Adaptive results include normalized leaf bounds and refinement levels, allowing
the interface to interpolate plan, section, and 3D thermal previews without
requiring a structured point layout. Isostatic topography continues to use the
uniform sampler because it integrates density along structured vertical
columns.

Adaptive calculations accept:

```js
const result = await gwbRuntime.run({
  wbText,
  gridText,
  resolutionLimit: 96,
  sampling: "adaptive",
  adaptiveOptions: {
    baseResolution: 4,
    maxDepth: 4,
    maxCells: 100000,
    temperatureTolerance: 25,
    compositionTolerance: 0.05,
    topographyTolerance: 250
  }
});
```

The standalone browser smoke test is available at
`/tests/wasm-smoke.html` while the development server is running.
